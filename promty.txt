📖 Booking Conflict Resolution – Full System Description

We are building a room management system with NestJS (backend) and Next.js (frontend).
The core rule is: no room can have two overlapping bookings.

The system must enforce this rule while also providing alternative suggestions when conflicts arise.
There are three types of users:

Super Admin / Secretary: manages bookings, resolves conflicts.

Requester (Normal User): submits booking requests.

System: enforces business rules and provides suggestions.

1. Booking Approval Flow
Step 1. Check for Conflicts

When the super admin/secretary tries to approve a pending booking:

Query the database for existing approved bookings in the same room where the requested interval overlaps:

SELECT * FROM bookings
WHERE room_id = :room_id
AND status = 'approved'
AND (requested_start < existing_end AND requested_end > existing_start);


If such a booking exists → reject the approval attempt.

Return an error to the frontend:

“Impossible to approve. Another booking is already approved in this room for that time.”

Step 2. Handle Conflicting Requests

If multiple requests exist for the same room/time:

Only one can be approved (e.g., director > staff).

Others go into a conflict resolution process (handled by the secretary).

2. Conflict Resolution Workflow (Secretary)

When a booking is rejected due to conflict:

Step A. Search for Alternatives (Same Time Slot)

Look for other rooms that:

Are free during the requested time.

Have capacity ≥ required capacity.

If found → suggest these rooms to the requester.

Step B. Search Nearby Slots

If no alternative room is found at the same time:

Same Room First:

Check if shifting the time by +30 minutes or –30 minutes frees the requested room.

Keep the same duration.

Other Rooms Next:

Search other rooms that are free at these adjusted times.

Step C. Build Two Tables

The secretary dashboard must show:

✅ Possible Alternatives Table:

Room name, Suggested time, Capacity, Action (Approve / Suggest).

❌ Rejected Requests Table:

Booking requests that could not be placed anywhere.

3. Frontend Behavior
For Normal Users

When submitting a booking that conflicts with an approved one:

Show error:

“Your requested time conflicts with another approved booking.”

Provide option to view alternative suggestions (generated by secretary).

For Super Admin / Secretary

A Conflict Resolution Panel in the dashboard:

Lists all pending/conflicting bookings.

Shows suggested alternatives.

Allows secretary to:

Approve an alternative.

Suggest alternatives back to the requester.

Mark a booking as rejected.

4. Algorithm Summary (Step by Step)

Approve Attempt

When approving a booking, check overlaps in the same room.

If overlap → throw error “Impossible to approve.”

Conflict Handling

If multiple requests exist → approve only one, send others to conflict resolution.

Alternative Search

Step A: Look for other rooms free in the same time slot.

Step B1: Try original room with ±30 min shift.

Step B2: Try other rooms with ±30 min shift.

Result Building

If alternatives found → show them.

If none → move to rejected table.

5. Example Scenario

Request A: Room X, 1:00–3:00 (Director).

Request B: Room X, 1:00–1:30 (Staff).

Process:

System auto-approves A (priority).

System rejects B for conflict.

Secretary searches alternatives:

No free room 1:00–1:30.

Room X is free at 1:30–2:00 → Suggest.

Secretary either approves alternative or rejects.

6. Database Notes

Booking table must have:

id

room_id

user_id

start_time

end_time

capacity_required

status (pending, approved, rejected)

reason (optional, e.g., “conflict with booking #123”).
